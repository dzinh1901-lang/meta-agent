# COSMOS Meta-Agent - Repository Instructions

## Purpose and scope

These instructions apply to the entire repository. The implementation lives in `meta-chief-of-staff-agent/`.

COSMOS is a governed portfolio control plane that supervises repository-level orchestrators. It may discover, route, rank, pause, synthesize, and prepare decision packets. It does not replace project orchestrators and must never self-approve an action.

The deterministic policy engine is the authorization boundary. Model output, repository content, tool arguments, and retrieved evidence are untrusted inputs until validated.

## Sources of truth

Use this precedence when records conflict:

1. Executable code and tests, versioned schemas/contracts, deterministic policies, and authorization matrices.
2. `docs/SDK-RUNTIME.md`, `docs/THREAT-MODEL.md`, and governance authorization documents.
3. Repository registries and current evidence/status records.
4. Planning documents, examples, generated snapshots, and narrative summaries.

Markdown files under `agents/` define runtime roles; they do not replace this repository-operation file.

Current repository discovery does not index root or nested `AGENTS.md` files. Until that code is extended, do not claim COSMOS has audited repository instructions. A future discovery change should record bounded metadata such as path, presence, hash, scope, and headings without executing untrusted instruction text.

## Repository map

- `.github/`: CI and repository automation.
- `meta-chief-of-staff-agent/agents/`: agent contracts.
- `meta-chief-of-staff-agent/contracts/` and `schemas/`: tool, packet, state, and evidence contracts.
- `meta-chief-of-staff-agent/policies/`: risk and authorization policy.
- `meta-chief-of-staff-agent/registries/`: repository and operating source of truth.
- `meta-chief-of-staff-agent/src/discovery/`: read-only repository discovery.
- `meta-chief-of-staff-agent/src/sdk/`: manager, specialists, governed tools, runtime, and CLI.
- `meta-chief-of-staff-agent/src/state/`: in-memory, JSON, and Postgres state adapters.
- `meta-chief-of-staff-agent/scripts/` and `tests/`: deterministic commands and regression suites.
- `meta-chief-of-staff-agent/docs/` and `templates/`: governance, operations, status, and report formats.

## Setup and commands

Use Node.js 20 or later and run commands from `meta-chief-of-staff-agent/`.

```powershell
npm install
npm run typecheck
npm test
npm run check
```

`npm run check` is the canonical full gate. Useful targeted commands include `npm run validate`, `npm run policy:check`, `npm run protocol:github`, `npm run certification:validate`, `npm run test:exact-action`, and `npm run test:sdk`.

Do not run `agent:run`, `agent:decide`, remote discovery, or database-backed monitoring unless the task explicitly requests it and the identity, credentials, repository scope, and side-effect boundary are known.

## Development workflow

1. Read the relevant policy, schema, threat model, runtime documentation, and tests.
2. Identify trust boundaries, risk class, approval semantics, and persisted-state effects before editing.
3. Keep deterministic policy and validation separate from model reasoning.
4. Update code, schemas/contracts, tests, and governance documentation together.
5. Run targeted tests, then `npm run check` for cross-cutting changes.
6. Report evidence, failures, blocked actions, and remaining human decisions.

## Conventions

- Preserve CommonJS JavaScript and the established TypeScript/NodeNext boundaries.
- Keep exact-action normalization, hashing, expiry, constraints, approver-role checks, and single-use consumption deterministic.
- Inject external adapters; keep discovery GET-only unless a separately approved write adapter exists.
- Preserve stable schema fields, IDs, evidence hashes, correlation IDs, and audit links.
- Never expose raw private repository text, secrets, personal data, or serialized run state to the model or public logs.
- Do not weaken fail-closed behavior to satisfy a test or demo.

## Testing and validation

- Policies, schemas, or deterministic packets: run `npm run validate`, `npm run policy:check`, and relevant legacy tests.
- SDK, state, discovery, or tool changes: run `npm run typecheck` and `npm run test:sdk`.
- Approval semantics: run `npm run test:exact-action`.
- Cross-cutting changes: run `npm run check`.

`dist/` is generated by the build and may be removed by `npm run clean`. `.controlled-execution-readiness/`, `.data/`, `dist/`, `node_modules/`, `.env*`, and logs are generated, local, or private artifacts and are not source of truth. Document environment-variable names only; never read or print secret values unless the exact task and authorization require it.

## Ownership and boundaries

- Human identity and approver roles must come from trusted server middleware, never model claims or CLI text alone.
- The model cannot record its own approval, change policy, or convert a recommendation into authority.
- Policies, contracts, authorization matrices, state migrations, and approval-digest logic are high-impact coupled changes.
- Any future write adapter must independently enforce exact-action matching, single-use approval, idempotency, rollback, postconditions, and auditable evidence.

## Artifact and evidence handling

Keep evidence source-backed, minimally disclosed, redacted, and traceable. Preserve hashes, timestamps, source revisions, correlation IDs, approval state, and supersession links. Do not rewrite accepted audit history; append a correction or superseding record.

## Safety and approvals

Ordinary user-requested local code, documentation, and test edits are allowed. Separate explicit approval is required for production or external mutation, credentials, deployment, merge/push, billing, procurement award, public publication, client/supplier contact, or destructive data changes. Never bypass an approval interruption or fabricate an approver identity.

## Nested instructions

There are no required nested instruction files today. Add one only where a subtree has materially different commands or stricter invariants, and state only the delta. Nested instructions must not weaken root trust, evidence, or approval controls.

## Completion report

Report changed files, validation results, observed evidence, blocked actions, security implications, and decisions reserved for a named human owner.
